# Per-user Inno Setup installer next to the portable zip

UsageQuotaTray ships two ways: a per-user installer built with Inno Setup 6 and the portable zip. The installer runs without admin rights (`PrivilegesRequired=lowest`, no all-users option), installs to `%LOCALAPPDATA%\Programs\UsageQuotaTray` by default, adds a Start menu shortcut and an Apps & features entry, and its uninstaller runs the app's own removal (`usagequotatray.exe --remove-from-pc`) so Claude Code's `statusLine` is put back before any file goes. The uninstaller fails closed: it goes on only when that removal ran and exited 0 (removed) or 2 (the `statusLine` is back, some of the app's own entries stayed); if it could not be started or exited with any other code (1, the `statusLine` could not be put back, or a crash), it says what happened and removes nothing. We rejected MSIX: it needs a trusted signature to install, and packaged identity replaces the app's own AppUserModelID, which changes how toasts are attributed. We rejected WiX/MSI: per-user MSI installs are awkward (ICE rules, `ALLUSERS` and the per-user folder conventions) for no gain over Inno for a single-folder app. We rejected shipping only the zip: an installer gives a Start menu entry, an uninstall entry and upgrades in place, which most users expect.

## Consequences

- The installer's AppId and default folder are fixed for good. The Start-with-Windows value and Claude Code's `statusLine` point at the installed exe's path, so a new AppId would install a second copy beside the first, and a new default folder would leave both pointing at the old one.
- The installer writes the Run value in exactly the app's format, and only on a fresh install when the task is chosen; after that the app owns Start with Windows, and an upgrade only re-points an existing value at the installed exe. `crates/app/tests/installer.rs` checks the script against the app (Run value, tasks, `AppMutex`, `--quit`, the shortcut's AppUserModelID, the removal command and the exit codes the uninstaller accepts).
- Every running tray holds the `UsageQuotaTray.Running` mutex and waits on the `UsageQuotaTray.Quit` event, both in the session's namespace. Setup (in `InitializeSetup`, on an upgrade) and Uninstall (at `usAppMutexCheck`, after the user confirmed) run `usagequotatray.exe --quit`, which sets the event and waits up to 10 seconds for the mutex to go; the `AppMutex` check then asks the user only if a tray is still running. Setup starts the tray again only if one was running.
- The installer is unsigned, so SmartScreen warns on first run. The zip keeps today's behaviour, including the in-app removal; an installed copy hands removal to its uninstaller.
